# Assumptions and limits of the evidence

ThermoWeave studies declared synthetic scenarios. Its charter excludes calibrated-cell, safety, certification, lifetime and production-control claims. Native software verification, solver convergence, agreement with another implementation and validation against measurements answer different questions. This documentation package does not perform a new physical validation. [PROJECT_CHARTER.md:1–43](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/PROJECT_CHARTER.md#L1-L43) [SECURITY.md:1–19](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/SECURITY.md#L1-L19)

## What the model assumes

Each cell is a lumped thermal mass with constant resolved capacity. Conductance edges, boundaries and current histories are supplied, not inferred from materials, fluid geometry or an electrical network. Electrical heat uses a linear resistance correction and optional fixed entropy coefficient; SOC is a simple efficiency-adjusted integral of imposed current. There is no terminal-voltage/OCV solve, electrochemical diffusion, aging law, phase-change, radiation or thermal-runaway propagation model in the native RHS. Absence is scoped to the inspected native path, not to generic teaching code embedded in the browser. [src/+thermoweave/simulate.m:54–68](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/simulate.m#L54-L68) [src/+thermoweave/+electrical/heatGeneration.m:1–10](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Belectrical/heatGeneration.m#L1-L10) [src/+thermoweave/+electrical/socDerivative.m:1–7](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Belectrical/socDerivative.m#L1-L7)

The 3-D topology has three coordinate axes and inter-layer exchange but one temperature per cell. A cuboid drawing does not establish internal three-dimensional cell thermal resolution. Surface masks are descriptive; scalar/vector boundaries apply to configured nodes through expanded values rather than a geometric face area integration. All conductances are resolved W/K. If a user has $h$ in W/(m² K), that user must deliberately compute $H=hA$ for an appropriate area before supplying it. [src/+thermoweave/+thermal/buildTopology.m:1–178](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Bthermal/buildTopology.m#L1-L178) [DECISIONS.md:69–75](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/DECISIONS.md#L69-L75)

Coolant is a forward quasi-steady segment balance, with no fluid thermal capacitance or travel-time state. Reversed experiments reorder node/segment assignments with positive flow. A pump-loss fault may set effective flow to zero even though nominal zero flow is rejected. The epsilon denominator prevents division by zero but is not a verified physical zero-flow model. Active cooling assumes an available heat sink and uses a net extraction proxy rather than electric energy consumption. [src/+thermoweave/+coolant/evaluate.m:1–68](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Bcoolant/evaluate.m#L1-L68) [src/+thermoweave/+coolant/march.m:1–8](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Bcoolant/march.m#L1-L8) [src/+thermoweave/+uncertainty/applyFaults.m:1–34](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Buncertainty/applyFaults.m#L1-L34)

## Numerical and control limits

Control is updated at output intervals and held during integration. Therefore changing `outputStep_s` changes both recording and feedback behavior. The baseline deadband implementation has a unit/name mismatch, and the main path supplies equal weights. The advanced controller optimizes a reduced one-horizon zonal approximation with command/rate limits; it does not impose full cell temperature, SOC or safety constraints. Do not describe fallback as optimization success. [src/+thermoweave/simulate.m:8–25](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/simulate.m#L8-L25) [src/+thermoweave/+control/baselineController.m:1–17](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Bcontrol/baselineController.m#L1-L17) [src/+thermoweave/+control/advancedController.m:1–60](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Bcontrol/advancedController.m#L1-L60)

SOC is not clipped and current profiles/fault discontinuities are not all scheduled as separate ODE stop times. Tolerances are local solver controls, not a global physical-error guarantee. The residual is formed from the same RHS terms used to compute derivatives, so a small value cannot rule out integration error, wrong parameters or omitted physics. An independent integrated balance and controlled tolerance/output-step refinement are proposed future gates. [src/+thermoweave/simulate.m:1–102](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/simulate.m#L1-L102) [tests/integration/TestSimulationIntegration.m:51–83](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/tests/integration/TestSimulationIntegration.m#L51-L83)

## Distribution and fault interpretation

Seeded variability is a demonstration distribution. The `R0CV` number is used as the lognormal normal-scale parameter; it is only approximately the resulting coefficient of variation for small values. Edge variability has a static mismatch for multi-layer rectangular layouts; the ordinary 3-D scenario uses `cuboid`, which takes a different edge-count path. Fault event records reflect supplied declarations and controller fallbacks, not independent diagnostic detection. Do not infer sensor-detection precision/recall or fault localization performance from those records. [src/+thermoweave/+uncertainty/applyVariability.m:1–36](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Buncertainty/applyVariability.m#L1-L36) [src/+thermoweave/simulate.m:69–84](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/simulate.m#L69-L84)

## Historical prose and optional models

Historical root/model/readme claims remain preserved. This dated source review clarifies three overstatements: row vectors are often flattened rather than rejected; `samplePeriod_s` is not the main control clock; and the residual is not an independent integrated balance. Read these clarifications when using old descriptions. The optional Simscape gate reports availability/policy/model status, and the mapper labels its output `MAPPED_NOT_GROUND_TRUTH`. No comparison, physical calibration or generated model completion is asserted. [docs/model.md:1–136](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/model.md#L1-L136) [simscape/buildThermoWeaveModel.m:1–105](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/simscape/buildThermoWeaveModel.m#L1-L105) [simscape/mapSimscapeResults.m:1–132](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/simscape/mapSimscapeResults.m#L1-L132)

The [roadmap](../../ROADMAP.md) proposes native edge-case, energy, timing and provenance work. Dates and owner roles are proposals; none converts an unexecuted gate into a passing result. Any future measured-data program must establish permission, acquisition/calibration records, uncertainty, parameter estimation, a held-out evaluation protocol and model-discrepancy limits before publishing accuracy claims.
