# Architecture and execution boundaries

Reviewed on 2026-11-19 against source `5f29e34788b0f7ee58e2feeafc4df5d48a9a687a`. ThermoWeave contains a synthetic graph electrothermal model, a one-mass browser lesson, stored browser playback, and an optional Simscape mapping route. Their shared subject does not make their outputs interchangeable. [Documentation index](../INDEX.md) · [equations](../math-and-physics/EQUATIONS_AND_DERIVATIONS.md).

## Native model

`startup` adds `src`, `simscape` and `tools` to the MATLAB path. `runDemo` creates a shortened default run when no scenario is supplied; `thermoweave.simulate(source)` loads and recursively merges a scenario, validates it, draws seeded variability, constructs the topology, advances temperature/SOC and assembles a canonical result. The public wrapper requires a `source` argument; use `[]` for defaults. The loader itself also supports no argument. Examples live outside the paths added by `startup`. [startup.m:1–10](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/startup.m#L1-L10) [runDemo.m:1–11](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/runDemo.m#L1-L11) [src/+thermoweave/+config/loadScenario.m:1–31](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Bconfig/loadScenario.m#L1-L31) [src/+thermoweave/simulate.m:1–25](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/simulate.m#L1-L25)

The graph contains one thermal mass and one SOC value per cell. Cartesian node order is `r + (c-1)*rows + (layer-1)*rows*columns`; edges connect immediate axial neighbors. Staggered layouts use a distance-based neighbor rule in each layer and aligned cross-layer edges. The Laplacian is `B'*diag(g)*B`, with positive edge conductances. Surface masks and coordinates describe the topology; a mask alone does not install a heat boundary. Zones partition contiguous node indices. [src/+thermoweave/+thermal/buildTopology.m:1–178](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/%2Bthermal/buildTopology.m#L1-L178)

Every output interval computes a sensed zonal command, applies actuator faults, holds that command while `ode15s` or `ode45` integrates, then stores the endpoint. Current, heat and boundary signals are evaluated at each declared sample's state/time. The last row repeats the previous command and evaluates final-state signals. `controller.samplePeriod_s` is not an independent scheduler here: `outputStep_s` and the possible shorter last interval set actual update times. Changing output spacing can therefore change closed-loop dynamics. [src/+thermoweave/simulate.m:8–59](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/src/%2Bthermoweave/simulate.m#L8-L59)

## Dependencies and data flow

| Producer | Consumer | Contract and boundary |
|---|---|---|
| Default configuration plus JSON/struct override | Validator and topology builder | `thermoweave.config/v1`; resolved synthetic assumptions, not measured calibration |
| Electrical, coolant, graph and fault functions | ODE right-hand side | Node temperature K, SOC fraction, current A; positive heat enters the cell |
| Sensor values and prior command | Baseline or advanced controller | Zone commands in `[0,1]`; advanced falls back visibly when unavailable or unsuccessful |
| Time histories and topology | Result/metric builders | `thermoweave.result/v1`, time-by-entity arrays and scalar metrics |
| Native simulations | `exportWebData` | `thermoweave.web/v1`, Celsius presentation arrays and retained metrics |
| Canonical result | MATLAB plots/dashboard/GIF | Presentation changes units to °C; does not rerun physics |
| Markdown/CFF chapter manifest | Reference renderer | Static HTML/MathML; no simulation, deployment or test runner |

The implementations and schemas are linked in the [interface catalogue](API_REFERENCE.md). Native result hashes include resolved configuration and available environment metadata. Hash equality is a reproducibility observation within a declared environment, not a cross-version determinism guarantee. ## Four reading and interaction surfaces

`docs/index.html` embeds its lesson JSON and pure JavaScript model. For this repository it selects `thermal`, a single heat capacity driven by constant heat and conductance. It has no native MATLAB connection. The exported `LabSimulation` object also contains nine other generic teaching kinds; their presence does not add those domains to the MATLAB core. The page exports 241 analytic samples of the selected model, including parameter columns. ## Optional adapter and ownership

`buildThermoWeaveModel` is a capability/policy/manifest gate, despite its builder-like name. It does not construct a Simulink model. `runSimscapeScenario` can open and simulate a supplied generated model only after gates succeed; inspect its origin, callbacks and manifest before that future operation. `mapSimscapeResults` checks selected canonical shapes and requires an externally supplied residual; mapping does not independently establish conservation or fidelity. No `.slx` or `.mdl` file exists in the reviewed canonical tree. [simscape/buildThermoWeaveModel.m:1–105](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/simscape/buildThermoWeaveModel.m#L1-L105) [simscape/runSimscapeScenario.m:1–40](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/simscape/runSimscapeScenario.m#L1-L40) [simscape/mapSimscapeResults.m:1–132](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/simscape/mapSimscapeResults.m#L1-L132)
