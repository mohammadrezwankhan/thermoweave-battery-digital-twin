# Browser model and interaction catalogue

The repository has six interactive/presentation entry surfaces, plus a redirect page. This inventory separates pure mathematics, stored data and personal learning state. All seven executable JavaScript units across the HTML/JS sources are syntax/indexed; their complete executable bodies were read. No DOM/visual/keyboard/browser execution was performed by this author. [Source scope](../SOURCE_EVIDENCE.md) · [native interfaces](API_CLI_AND_INTERFACES.md).

## Main analytic lesson

`docs/index.html` embeds JSON identical to `docs/lesson-config.json` and exports `LabSimulation` from a pure UMD script. Its exported properties are `MODEL_SPECS`, `getModelSpec`, `resolveParameters`, `evaluateModel`, `checkCheckpoint`. `getModelSpec` rejects an unknown kind. Recognized finite numeric inputs are clamped; invalid values fall back and unrecognized keys are ignored. Time is clamped to the selected horizon. Returned model specifications are not immutable deep copies. [docs/index.html:147–337](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/index.html#L147-L337)

For this repository the kind is `thermal`: one scalar heat capacity with constant heat/conductance, initial ambient, analytic exponential rise, time in minutes and Celsius display. The 60 min horizon exports 241 evenly spaced analytic samples; CSV columns include model time, each metric and each parameter. Four modules have two absolute-tolerance checkpoints each. Parameters/presets/expected values are source-defined; `node docs/reference/check_lesson.cjs` executes those eight fixtures without a DOM. [docs/lesson-config.json:1–320](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/lesson-config.json#L1-L320) [docs/index.html:338–475](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/index.html#L338-L475)

`checkCheckpoint` accepts `>=/gte`, `<=/lte`, `>/gt`, `</lt`, `==/=/eq/≈`. Equality uses absolute tolerance; non-strict comparisons include tolerance and strict comparisons do not. Invalid nonnumeric metric/target or unknown operator returns invalid status. These are fixture-comparison semantics, not a statistical confidence interval. [docs/index.html:320–337](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/index.html#L320-L337)

The UI adds `window.LabDashboard`, a frozen outer object with a copied-state snapshot getter and two pure API functions. Inputs, play/pause/reset, timeline, metric tabs, keyboard module tabs, presets, checkpoint checks, CSV/config download and clipboard/dialog actions are source-reviewed. Reduced motion stops automatic playback and responds to preference changes. Progress retains prior verified experiments even when the current parameters change; current displayed results reset. Clipboard/download/focus behavior still needs real browser verification. [docs/index.html:338–475](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/index.html#L338-L475)

## Other embedded teaching kinds

The shared pure script contains battery, thermal, degradation, grid, cooling, agents, markets, control, security and charging kinds. Their code uses simplified analytic/heuristic teaching equations: ohmic battery/SOC, exponential degradation, dispatch balance, cooling response, fluid queue, transaction arithmetic, second-order control, alert flow and charging taper. Only `thermal` is selected by this repository's lesson configuration. Static reading of the other branches and syntax checking does not constitute runtime/scientific validation, and these generic kinds are not native ThermoWeave subsystems. [docs/index.html:156–319](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/index.html#L156-L319)

## Native data playback

`docs/original-index.html` loads `docs/app.js`, which fetches `docs/assets/thermoweave-demo.json`. It offers scenario selection, play/pause, frame scrub, reduced-motion handling, heatmap/traces and a table. It assumes a 3×4 layout and twelve temperature entries per frame. `validatePayload` checks schema strings, scenario hash format, nonempty time length and temperature shape/finiteness; it does not fully validate time ordering, all metric/boundary/command fields or cryptographic content identity. An empty scenarios array passes that check but cannot initialize a current scenario. [docs/app.js:1–207](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/app.js#L1-L207)

Native `exportWebData` creates this separate `thermoweave.web/v1` format from five native scenarios. Legacy playback is not the main scalar lesson and does not simulate a new native result in the browser. The stored source data and metrics remain historical. [tools/exportWebData.m:1–72](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/tools/exportWebData.m#L1-L72) [artifacts/web-data/thermoweave-demo.json:1–1](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/artifacts/web-data/thermoweave-demo.json#L1-L1)

## Guides and animation archive

`docs/native-lessons.html` filters nine material cards by text and intersection of selected tags, displays counts and copies three command snippets with clipboard/fallback selection. Its catalogue records an older native source `e62c0d720aa92273e4b8c9a2b03977ba06045fd2` and a separate browser package provenance. This package adds navigation only; it does not silently rewrite those older snapshots. [docs/native-lessons.json:1–353](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/native-lessons.json#L1-L353) [docs/native-lessons.html:114–164](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/native-lessons.html#L114-L164)

`docs/portfolio/index.html` builds eight learning paths from its embedded configuration, validates pinned source URL construction, persists notes/review/motion state under a repository+revision local-storage key and exports a study plan. The explicit export field `execution_status: not_executed_by_this_guide` is retained. Search/level/tag filtering, empty states, dialog and manual review controls are source-reviewed, not a native executor. [docs/portfolio/lesson-config.json:1–373](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/portfolio/lesson-config.json#L1-L373) [docs/portfolio/index.html:437–468](https://github.com/mohammadrezwankhan/thermoweave-battery-digital-twin/blob/5f29e34788b0f7ee58e2feeafc4df5d48a9a687a/docs/portfolio/index.html#L437-L468)

`docs/animations/index.html` is an archive with `gallery.js`; media are loaded on explicit play and removed on stop. Its companion `waveform.html` draws illustrative sinusoidal curves controlled by rate, temperature and damping sliders. It starts paused and stops on hidden/reduced-motion changes. The curves have no native battery/thermal solver coupling and are not scientific evidence. The archive and unavailable-media labels remain unchanged.
